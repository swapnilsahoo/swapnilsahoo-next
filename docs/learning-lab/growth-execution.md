## What is genuinely automatic

All four website notes are publicly available from 21 October. The sitemap contains 104 URLs and the RSS feed contains four items. The archive remains available after the campaign. Website publication and the optional weekly email dates are separate, so early public access does not accelerate the email queue.

The public pilot saves feedback in the existing restricted enquiry store, with isolated per-email/per-lesson updates. It is separate from programme demand and paid enrolment. Adult/voluntary/privacy acknowledgements are required. Clarification contact and the four practice emails are separate optional choices, initially off. The newest response controls those choices across the pilot. A submission gives a saved reference; it does not claim an immediate email, observed completion or assessed outcome.

The local Gmail operation uses the owner's existing connection through the documented [Codex app-server JSONL protocol](https://learn.chatgpt.com/docs/app-server). Code discovers the installed Gmail tools, verifies the account and invokes only the fixed read/send actions needed by this campaign. It starts no model turn: an assistant does not interpret consent, choose recipients or generate messages. No connector credentials are extracted, exported or uploaded, and no global app permissions are changed.

Only the three private invitation threads and correspondence from real, separately consenting pilot contacts are in scope. The latest server-written consent marker is parsed strictly, and the protected server records are read again immediately before each send. Incoming mail and learner text are data; neither is executed as an instruction. No list is scraped, no contact is added to a newsletter, and no nonresponder receives an automatic reminder.

Withdrawal checks include Spam and Trash, validate the exact sender/owner recipient and ignore quoted older text. STOP suppression persists across later form changes. Only a fresh same-address message with an exact standalone `RESUBSCRIBE` or `RESUBSCRIBE LEARNING LAB PRACTICE` in its current body or subject clears that suppression; the separate notes choice must still be on. Ambiguous reads or pagination withhold sending. New practice-email sends stop after **13 November 2026, 23:59:59.999 IST**; health checks and private feedback review can continue through 18 November.

At most five predefined practice messages can be attempted in one run, with no added CC/BCC or new outreach. Each attempt is recorded atomically before dispatch. Before sending, the operator searches across all folders for prior matching mail and checks the actual SENT label, exact recipient, unique subject and original HTML. Ambiguous outcomes remain pending for later reconciliation, rather than being retried blindly or disabling all future reads. Sending, provider acceptance and inbox delivery remain different facts.

This local operation requires the Windows owner signed in, the computer awake/online and a valid Codex/Gmail account connection within its provider limits. Missed work can run when the machine becomes available. It is not a continuous cloud email service. The task uses the limited interactive owner identity, requires network, ignores overlapping starts and has a 15-minute limit. The runner has its own 13-minute budget and a 14-minute outer process-tree watchdog; it does not wake the computer or store a Windows password. CLI updates can be recovered from the owner's already installed official extension without downloading or installing anything.

Actual complete operator results are stored in the owner-only `.data/learning-lab-campaign-2026/` reports. The first `latest.json` records `passed: true`, `phase: complete`, `gmailProfileVerified: true`, `signedOut: true`, no pending reconciliation and zero sends.
