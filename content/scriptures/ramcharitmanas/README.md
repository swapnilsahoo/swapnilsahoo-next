# Ramcharitmanas source-text corpus

This directory contains a deterministic, versioned ingestion of all seven JSON files in the openly licensed [WirelessAlien/Ramcharitmanas](https://github.com/WirelessAlien/Ramcharitmanas) dataset. The exact upstream revision is pinned to commit [`a8734282b3f95648032a53447f08ad77acb2ecd4`](https://github.com/WirelessAlien/Ramcharitmanas/tree/a8734282b3f95648032a53447f08ad77acb2ecd4). This is the complete pinned numbered dataset, not by itself the complete selected work: the seven files omit 39 opening invocations across the seven kāṇḍas (23 Sanskrit and 16 Awadhi records). Those openings are kept separately in `opening-invocations.v1.json` with their own public-domain scan provenance.

The opening supplement is a diplomatic transcription of the named 1925 Belvedere Press witness. It preserves that edition's lexical readings and printed hyphenation even where IIT Kanpur or common modern printings differ; it is not silently harmonized with the numbered dataset.

The upstream repository describes itself as “The Ramcharitmanas in Json,” contains Devanagari source text without translation or commentary, and acknowledges the [IIT Kanpur Ramcharitmanas](https://www.ramcharitmanas.iitk.ac.in/) site as its data source. Its dataset is released under [The Unlicense](https://github.com/WirelessAlien/Ramcharitmanas/blob/a8734282b3f95648032a53447f08ad77acb2ecd4/LICENSE). A verbatim copy is stored here as `UPSTREAM-LICENSE.txt`; the manifest pins its SHA-256 alongside all seven source files.

## Rebuild and verify

From the repository root:

```powershell
node scripts/import-ramcharitmanas.mjs --write
node scripts/import-ramcharitmanas.mjs --check
```

Both modes download the seven source files and the license into memory from the immutable commit URL, verify byte counts and pinned SHA-256 checksums before parsing, and validate the expected 1,074 units. `--write` reproduces the shards and manifest; `--check` fails if any generated byte differs.

## Preservation policy

- Source array order is preserved: Bālakāṇḍa, Ayodhyākāṇḍa, Araṇyakāṇḍa, Kiṣkindhākāṇḍa, Sundarakāṇḍa, Laṅkākāṇḍa, and Uttarakāṇḍa.
- Each upstream array element stays one unit. Embedded headings and groupings such as `चौपाई` and `दोहा/सोरठा` are not split or interpreted.
- Inside the source-text string, CRLF or lone CR is converted to LF and Unicode NFC is applied. Nothing is trimmed, respaced, translated, transliterated, corrected, or otherwise rewritten.
- Stable IDs use the kāṇḍa slug and one-based source-array position. A contiguous global sequence runs across all seven kāṇḍas.
- `sourceVerseNumber` preserves the exact numeric token lexeme present in the upstream JSON. It is not a unique identifier: because the upstream field is a JSON number, serialization already made positions such as `1.10` indistinguishable from `1.1`. The generated `sourceIndex`, stable ID, and global `sequence` avoid this ambiguity without guessing at lost characters.

## Scope and limitations

“Complete pinned dataset” here means that all 1,074 numbered units from all seven files at the pinned revision are present and checksum-verifiable. The combined website reader adds the 39 separately sourced openings, creating 1,113 top-level records in this declared edition topology. Neither count is presented as universal across editions, and neither asserts a critical or diplomatic edition. These generated files contain source text only; they make no claim to supply English or Hindi translation, pronunciation, grammatical analysis, word-by-word glosses, or commentary.
